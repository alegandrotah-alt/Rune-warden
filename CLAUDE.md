# Rune Warden: notes for working on this repo

- Fantasy roguelite tower defense with an auto-battler shop (portrait or landscape). Sibling of Gate Rush (alegandrotah-alt/gate-rush-android) and built the same way.
- Edit the game in `src/`, never `www/index.html` (it's generated). `node tools/build.js` assembles it.
- `src/game/*.js` files are concatenated in name order into one script inside one IIFE (opened in `00-core.js`, closed in `10-loop.js`); they share one scope, so order matters for top-level `const`s.
- Before pushing, run `node tools/build.js && node tools/sim.js --runs 6`; CI also runs `tools/browser-check.js` (set `CHROME_PATH` locally).
- The sim loads the game with no DOM at all: keep DOM-only code behind `DOM` / `$()` null checks so game logic runs headless.
- Sprite sheets in `www/gfx/` are rendered offline from CC0 KayKit / Quaternius / Kenney models with a rim light: heroes `h_<key>.png` (10 square cells of 256: idle 0-3, attack 4-9, facing right), monsters `m_<key>.png` (6 walk cells of 256), `keep.png` and `keep_<colour>.png` skins (320), `props.png` (192 cells), `props2.png` (graveyard/ember props, 160 cells), `props3.png` (bog/frost/dune props, 192 cells; see `OBS_SETS`/`EDGE_SETS` in `01-data.js`). `frame()` reads the cell size of `h_`/`m_`/`props3` sheets from the image height, so older 160px sheets still work.
- Music in `www/music/` (one track per act plus menu and boss, see CREDITS.txt); sound effects (`sp_*` spell sounds, `m_*` monster hits) and particle textures are embedded from `src/assets/`.
- Two layouts, picked by the window shape (`ROT` in `00-core.js`, `body.port` in CSS): landscape (road left to right) and portrait (the same field turned: spawn on top, keep at the bottom). Field coordinates never change. `sx`/`sy` map into layout space and are only valid for ground art drawn after `gnd()` (it swaps axes in portrait); anything upright (sprites, text, bars, plinths) takes its anchor from `scr(x,y)` and is drawn after `upr()`. `unscr()` turns a screen point back into the field, `fieldBox()` gives the field's screen rectangle, `FB` the unzoomed one the bench strip hangs under (`bottomLayout()`: one strip in landscape, bench row plus racks in portrait). Facing uses `fc(o)` (`face` along the road, `fy` across it).
- Zoom: `ZM.z` from 1 (whole board) to `ZMAX`; phones start zoomed in (`defZoom`, remembered in `SET.zoom`); − / + buttons, pinch, wheel, double-tap; one finger pans when zoomed. The bench and racks never zoom.
- The board is 16×10 pointy-top hexes in offset rows: use `hx(c,r)`/`hy(r)` for centres, `cellOf(x,y)` for the hex under a point, `nbrs(c,r)` for neighbours and `hexPath()` to draw one. Never assume square tiles.
- Gates (`R.field.gates`, `02-run.js`): gate 0 is the west portal (rows `SPAWN_ROWS`, monsters walk in from outside); the others are cells (north/south edge gates, breaches) where monsters appear. `flow()` fails if any gate loses its road, so `canPlace` keeps every gate open. `tagGates()` gives each wave entry a gate `g` (`gatePlan()` decides how many open); `R.field.routes[id]` is each gate's road. `openRift()` makes a temporary breach mid-wave (act bosses at half health, the Devourer).
- Terrain is `R.field.ter` (`TER`: 1 hill, 2 mud, 3 thorns, 4 water; water is also `blk` 2). Biomes: `R.bio[act]` picks an entry of `BIOMES` or null; always read act data through `actD(act)`, never `ACTS[...]` directly. `obs` in a biome indexes `OBS_SETS`/`EDGE_SETS`/`BACKS`/`AMBK`.
- Knockback: `knock(m,hexes)` pushes a walker up the flow field (Bruiser trait, Gore, `ab.kb`).
- Run flow: every floor is one auto-battler round. Map rooms (`05b-map.js`) are fights (`NODES[t].fight`: battle, elite, boss) or rooms without monsters (`05c-rooms.js`: rest, merchant, treasure, event, plus the oracle at the start). Phases: plan, wave, reward (recruit pick), pick (relics), room, over; after a fight `R.queue` plays the screens in order via `advance()`. `roomView()` describes a room for both the screen and the sim bot.
- Keep guardians live in `04c-keep.js` (`GUARDS` data in `01-data.js`, `META.gl` levels, `META.geq` stationed); frontline auras are computed in `calcTraits()` into `h.au`, and monster-side zones use `R.b.fl` built every battle tick.
- Onboarding stages (`08d-onboard.js`): stage 0 first run, 1 adds events/merchant/potions/oracle, 2 adds keep guardians; `stage()` gates them and `SET.allSys` turns everything on. The sim always plays with all systems on. Hint cards (`TIPS`) show once each; add `&notips` to the URL in screenshot scripts.
- Icons are drawn (`00b-icons.js`): `icon(name)` gives SVG for the page, `drawIcon()` paints the same art on the canvas; data entries get `.ic` (SVG) and `.icn` (name) from `applyIcons()`. Don't use emoji-prone text symbols for UI icons.
- `saveRun()` only saves a run with `R.live` set (a run the player started); the placeholder run behind the menu must never overwrite a saved run.
- Balance: `node tools/sim.js --runs 80` (strong bot) should land around 10-25% wins with deaths spread over act III; `--bot pacifist` must not clearly beat it; `--fuzz` hands out random relic piles. The bot should almost never beat the Devourer, and `--god` (★3 board with items) only rarely.
- Gameplay randomness that must repeat in a daily challenge (shops, waves, map, field, relic offers, events) goes through `rng()`/`rndS()`, not `Math.random`.
- Bump the cache name in `www/sw.js` when files in `www/gfx` or `www/music` are renamed or replaced.
- Pushing to `main` releases: Android APK on Releases (version = run number) and the web version on GitHub Pages.
